# Plan 12: Rebuild the CV PDF automatically

Read `CLAUDE.md` and `_CONTEXT.md` first. Effort: S to M. Model: Sonnet is fine.

## Goal
`cv/Angelo-Boutalikakis-CV.pdf` is a print export of `/cv/`. Today it is
regenerated by hand after each CV edit, which is easy to forget. A GitHub
Action should rebuild it whenever the CV page, the stylesheet, the fonts or
the headshot change on `main`.

## Steps
1. Add `scripts/cv_pdf.cjs`: serve nothing itself; take a base URL argument,
   open `<base>/cv/` in Playwright Chromium, emulate print media, wait for
   `document.fonts.ready`, write the PDF (A4, `printBackground:false`, 15 mm
   margins). Same settings as the command in the comment at the top of
   `cv/index.html`; update that comment to point at the script.
2. Add `.github/workflows/cv-pdf.yml`: on push to `main` with `paths:`
   `cv/index.html`, `assets/site.css`, `assets/fonts/**`, `assets/headshot.jpg`,
   plus `workflow_dispatch`. Steps: checkout; setup-node; install Playwright
   with Chromium (`npx playwright install --with-deps chromium`); start
   `python3 -m http.server` in the background; run the script; if the PDF
   changed, commit it as the Actions bot (mirror `refresh.yml`'s commit step,
   including its `[skip ci]` convention if it uses one) and push.
   `permissions: contents: write`.
3. Guard against loops: the PDF itself is not in `paths:`, so the bot's commit
   does not retrigger the workflow.
4. PDF output differs byte-for-byte between runs (timestamps). Compare text
   content (for example with `pdftotext` from poppler-utils, installed in the
   workflow) and skip the commit when only metadata changed.
5. Document it in README (one short paragraph) and remove the manual step
   from `CLAUDE.md` practical notes if one is listed.

## Acceptance
Workflow YAML valid; the script reproduces the current PDF locally (same page
count, same text); a no-op run commits nothing; `python3 scripts/check.py`
passes.
